# Plan: Phase 21 - High-Resolution Proxy System (Tiered Sync)

## 1. Problem Statement (RCA)

- **Bottleneck**: Moving 100GB+ of original RAW/High-Res JPEG assets over local WiFi to multiple kiosks is unscalable and slow.
- **Goal**: Implement "Tiered Sync" where only tiny thumbnails and medium previews are pushed to kiosks. Original files are kept on Master for physical fulfillment.

## 2. Technical Architecture

### A. Tiered Export (Master)

- **Source**: `UPLOAD_DIR/{albumId}/{photoId}.ext` (and accompanying `_preview`, `_tiny`).
- **Target**: `KIOSK_UPLOAD_PATH/album-{id}-{ts}/`.
- **Logic**:
  - Filter out originals.
  - Copy only `*_preview.*` and `*_tiny.*` files.
  - Result: Bandwidth reduction by ~95% per sync.

### B. Intelligent Metadata

- Update `metadata.json` generated by Master to include explicit mapping:

  ```json
  {
    "photos": [
      {
        "id": "abc-123",
        "previewUrl": "photos/abc-123_preview.jpg",
        "thumbnailUrl": "photos/abc-123_tiny.jpg"
      }
    ]
  }
  ```

### C. Sync Manager Finalization (Master)

- Wire `SyncManager.ts` to the actual `DatabaseManager`.
- Implement persistence for `MUTATION` payloads (`create`, `update`, `delete`).
- Broadcast ACK and State Updates to all connected kiosks.
