# ClickFlash Electron Generator Rebuild Plan
**Classification:** Architectural Blueprint
**System:** ClickFlash Photography Ecosystem (Master Portal & Touch Kiosk)
**Status:** Authorized for Reconstruction

## 1. Executive Summary
Based on the 360-degree architectural scan of the current ClickFlash software ecosystem, this plan outlines the complete reconstruction of the "Electron Generator"—the core desktop application framework powering both the Master Portal and Touch Kiosk applications. The rebuild aims to harden offline-first durability, enforce strict inter-process security, and optimize build pipelines for production distribution.

## 2. Component Breakdown
The generator is divided into four primary functional units:

*   **Stator Core (Main Process):** Responsible for application lifecycle, system tray management, hardware bindings (printers, USB devices), and background process orchestration.
*   **Rotor Array (Renderer Process):** The user-facing interface, rebuilt using React 19 and Vite for maximum UI framerate and reduced memory pressure.
*   **Slip Rings (Preload & IPC):** The critical communication layer. Enforces strict `contextIsolation` and `nodeIntegration: false`. Only exposed channels (e.g., `kiosk:unlock`, `dialog:openDirectory`) are permitted to cross the boundary.
*   **Cooling System (Local Backend):** The integrated Express.js server (Ports 8090/8091) and `better-sqlite3` database engine, handling local network API requests and high-volume image processing queues without stalling the UI.

## 3. Material Specifications
All components must be fabricated using the following certified dependencies to ensure ecosystem compatibility:

*   **Engine Chassis:** Electron v39.2.7
*   **Processing Core:** Node.js v24.10.2 (Build Target Node 20 LTS)
*   **Renderer Material:** React v19.2.0 + Tailwind CSS v3.4.18
*   **Data Storage:** `better-sqlite3-multiple-ciphers` v12.8.0 (AES-256-GCM encryption enabled)
*   **Build Tooling:** Vite v7.2.4 (Frontend) + esbuild v0.27.4 (Backend) + electron-builder v26.8.1

## 4. Electrical Requirements
The generator operates within strict network and inter-process (IPC) boundaries:

*   **Master Portal Binding:** TCP Port 8090 (HTTP/WebSockets).
*   **Touch Kiosk Binding:** TCP Port 8091.
*   **Network Isolation Circuit:** The Touch Kiosk must programmatically reject all traffic not originating from a Private IP block (10.x.x.x, 192.168.x.x, 172.16.x.x).
*   **Signal Integrity (IPC):** All IPC calls must use constant-time comparison algorithms (e.g., `crypto.timingSafeEqual`) for sensitive operations like PIN unlock to prevent timing attacks.

## 5. Assembly Instructions
The reconstruction pipeline must follow this exact sequence to ensure a stable final build:

1.  **Preparation (`npm run clean`):** Purge all existing `dist`, `release`, and cache directories to prevent cross-contamination.
2.  **Backend Extrusion (`npm run build:backend`):** Use `esbuild` to bundle the Express server and background workers (`photoWorker`, `folderWorker`, `backupService`) into `dist/backend`. Native modules (e.g., SQLite, Sharp) must be marked as external.
3.  **Frontend Lithography (`npm run build`):** Use Vite to compile the React 19 application into static assets within `dist/master`.
4.  **Casing Assembly (`npm run package:v3`):** Use `electron-builder` to package the compiled assets, Node modules, and native binaries into a signed `.exe` installer.

## 6. Quality Control Protocols
Before any code is merged into the primary generator branch, it must pass the following automated safety checks:

*   **Static Scanning:** ESLint (`npm run lint`) must complete with zero warnings (`--max-warnings 0`).
*   **Structural Integrity:** TypeScript compiler (`tsc --noEmit`) must verify all type definitions across the monorepo.
*   **Dependency Audit:** Ensure no nested vulnerable packages exist within the dependency tree (Nightly CI scan).

## 7. Testing Procedures
The rebuilt generator must pass multi-stage stress testing:

*   **Sub-assembly Verification:** Run Jest unit tests (`npm run test`) to validate core utility functions, database queries, and data transformers.
*   **Full-System Load Testing:** Execute Playwright End-to-End tests (`npm run test:e2e:headed`) to simulate real-world photographer interactions, including high-res image ingestion, bulk album assignment, and kiosk pairing sequences.
