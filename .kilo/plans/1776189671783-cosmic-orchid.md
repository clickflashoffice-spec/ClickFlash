# Phase 1: Global Sync & Fleet Bridge Audit Plan

## Executive Summary

After deep-scanning the ClickFlash synchronization bridges, I identified **7 critical vulnerabilities** requiring immediate remediation before multi-master cloud deployment.

---

## Audit Findings

### Bridge 1: LOCAL BRIDGE (Master ↔ Touch) — Port 8090/8091

| Component | File | Status | Finding |
|-----------|------|--------|---------|
| WebSocket | `SyncManager.ts` | ⚠️ PARTIAL | Vector clocks implemented (L25-30), but CRDT not formalized |
| HMAC Signing | `orderExport.ts` | ⚠️ PARTIAL | `X-Kiosk-ID`, `X-Timestamp`, `X-Signature` present but **no replay prevention** (5-min window check missing) |
| Conflict Resolution | `SyncManager.ts:288` | 🔴 WEAK | `compareVectorClocks` returns 'concurrent' but merge is LWW, not true CRDT merge |
| Multi-Kiosk | `SyncManager.ts` | 🔴 GAP | No optimistic locking or mutex for simultaneous mutations |
| Heartbeat | `SyncManager.ts:35` | ✅ OK | 30s timeout, 10s check interval |

**Critical Issue**: If two Touch kiosks simultaneously mark the same order "Sold", the last-write-wins vector clock merge may lose data.

### Bridge 2: GLOBAL HYBRID BRIDGE (Multi-Master ↔ Cloud) — `cloudSyncService.ts`

| Component | Line | Status | Finding |
|-----------|------|--------|---------|
| desk_id Tagging | L595 | ✅ OK | All operations tagged with `desk_id` |
| Circuit Breaker | L493-504 | ✅ OK | OPEN/HALF_OPEN/CLOSED states implemented |
| DLQ | L32,652 | ✅ OK | Dead-letter queue for failed ops |
| Multi-Master Sync | `pullRemoteOperations` | 🔴 WEAK | Sequence-based LWW, but **no idempotency key** for duplicate prevention |
| Vector Clocks | `SyncManager.ts` | ⚠️ LOCAL ONLY | Vector clocks exist but **never propagate to cloud** |
| Conflict Resolution | `applyRemoteOperations` | ⚠️ TIMESTAMP | Uses `sequence_number` (Hub index), not hybrid logical clocks |

**Critical Issue**: When Master-A (Tunisia) and Master-B (Morocco) simultaneously push order updates, the Hub's `hub_index` ordering may not respect causality.

### Bridge 3: INGESTION BRIDGE (MoneyTrash → Cloud)

| Component | Status | Finding |
|-----------|--------|---------|
| Upload Chunking | 🔴 MISSING | No 5MB chunking visible in `cloudSyncService` |
| Cache Invalidation | 🔴 MISSING | No Management Hub cache invalidation on upload completion |
| Queue Concurrency | ⚠️ PARTIAL | `Promise.allSettled` at L513, but no concurrency limit |

**Critical Issue**: Large batch uploads from MoneyTrash may overwhelm Worker memory; no flow control.

## Roadmap: Fixes Required

### P1.1 — Implement Hybrid Logical Clocks (HLC) for Multi-Master

**Files**: `apps/master/backend/services/SyncManager.ts`, `apps/master/backend/services/cloudSyncService.ts`

1. Add `@clickflash/types` HLC type definition
2. Replace `VectorClock` with HLC timestamps that include physical + logical components
3. Ensure HLC propagates through both LAN (WebSocket) and WAN (CloudSync) bridges

### P1.2 — Add Replay Prevention to HMAC (Touch Export)

**File**: `apps/touch/backend/routes/orderExport.ts`

1. Add 5-minute timestamp window validation on Master side
2. Reject requests where `X-Timestamp` is outside window
3. Add `nonce` tracking in SQLite to prevent exact replay attacks

### P1.3 — Formalize CRDT for Order Mutations

**Files**: `apps/master/backend/services/SyncManager.ts`

1. Implement G-Counter CRDT for order item counts
2. Implement LWW-Register CRDT for order status fields
3. Add `hotelId`/`masterId` as mandatory fields in all sync payloads (ALLOWED_COLUMNS whitelist)

### P1.4 — MoneyTrash Chunking & Flow Control

**Files**: `apps/master/backend/services/cloudSyncService.ts`

1. Enforce 5MB chunk size for uploads
2. Limit `Promise.allSettled` concurrency to 3
3. Implement backpressure signaling when DLQ > threshold

### P1.5 — Cache Invalidation Webhook (MoneyTrash → Management Hub)

**Files**: `apps/gallery/backend/src/server.ts`

1. Add `/api/webhooks/ingestion-complete` endpoint
2. On photo upload completion, invalidate Management Hub React Query cache for affected `hotelId`
3. Use Cloudflare KV for cross-Worker cache invalidation

### P1.6 — Idempotency Keys for Cloud Operations

**Files**: `apps/master/backend/services/cloudSyncService.ts`

1. Generate `operation_id = sha256(table + record_id + desk_id + sequence_number)` as idempotency key
2. Store in `operation_logs.idempotency_key` column
3. Hub rejects duplicate `operation_id` with 200 (not error) to prevent double-application

### P1.7 — Fleet Tracking: Mandatory `hotelId`/`masterId`

**Files**: `packages/types/src/index.ts`, all sync routes

1. Add `hotelId: string` and `masterId: string` to `SyncPayload` interface
2. Reject any sync payload missing these fields (security: cross-tenant prevention)
3. Add database constraints: `hotelId` NOT NULL on all fleet-tracked tables
