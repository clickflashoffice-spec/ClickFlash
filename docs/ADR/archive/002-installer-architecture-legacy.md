# ADR 002: Unified Ecosystem Installer Architecture

## Status
Accepted

## Context
The ClickFlash ecosystem requires deploying two desktop applications (Master App and Touch App) along with specific Windows configurations (firewall rules, auto-start, power plans) to hotel/studio computers. Previously, these were installed independently or using basic `.bat` scripts, which lacked robustness, error reporting, and UX.

## Decision
We will use a **Unified Installer Architecture** based on **Inno Setup** as the wrapper, integrating the NSIS installers generated by Electron Builder.

### Architecture Flow
1. **Frontend Builds:**
   - Both `apps/master` and `apps/touch` use `electron-builder` to produce silent NSIS installers (`.exe`).
2. **The Wrapper (Inno Setup):**
   - A single Inno Setup script (`ClickFlash_Ecosystem_Setup.iss`) will bundle:
     - `ClickFlash Master OS Setup.exe`
     - `ClickFlash Touch Setup.exe`
   - It will run these installers silently in sequence.
3. **Bootstrapping (NSIS execution):**
   - The Master App NSIS installer is configured via `installer.nsh` to execute a PowerShell script (`windows-kiosk-setup.ps1`) after unpacking.
   - This script:
     - Configures the Windows Firewall for mDNS (UDP 5353) and HTTP/WS (TCP 8090, 8091).
     - Modifies the Windows Power Plan to 'High Performance' to prevent sleeping during active events.
     - Sets registry keys in `HKCU:\Software\Microsoft\Windows\CurrentVersion\Run` to automatically launch both the Master and Touch apps on Windows startup.

## Consequences
### Positive
- **Zero-Touch Deployment:** Hotel IT staff or photographers only need to run a single executable.
- **Resilience:** The applications will automatically recover and boot into kiosk mode after power failures or reboots.
- **Maintainability:** We still leverage `electron-builder` for the heavy lifting of Node/Electron packaging, while only using custom scripts for Windows-specific ecosystem needs.

### Negative
- Local testing of the installer requires a Windows environment and building both Electron applications first, which is time-consuming in CI/CD.
