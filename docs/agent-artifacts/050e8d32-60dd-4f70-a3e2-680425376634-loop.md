# ClickFlash Execution Loop

This document outlines the standard operating procedure (SOP) for making changes in the ClickFlash ecosystem.

## The Continuous Improvement Loop

1. **Analyze & Plan:** 
   - Before writing code, consult the `memory.md` and the `clickflash_total_ecosystem_roadmap.md`.
   - Identify the impacted boundary (e.g., Master app local sync vs. Gallery Cloudflare workers).
   - Draft the changes in `implementation_plan.md` for explicit approval.

2. **Execute:**
   - Execute the steps logged in `task.md`.
   - Ensure UI/UX changes adhere to the "Premium Aesthetics" constraint (Tailwind, animations).

3. **Verify:**
   - Run local linting and type-checking.
   - Run `pnpm audit` to ensure no new vulnerabilities were introduced.
   - Run end-to-end tests (e.g., Playwright) if applicable.

4. **Document:**
   - Update `walkthrough.md` with the completed actions.
   - Update `memory.md` with any new architectural insights or systemic constraints discovered.
