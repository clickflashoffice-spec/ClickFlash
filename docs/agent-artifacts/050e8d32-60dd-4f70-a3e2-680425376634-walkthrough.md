# Walkthrough: Phase 9 Automated Installation & Configuration

## Overview
We've completed the implementation of Phase 9 of the `tech_stack_modernization_roadmap.md`, which establishes zero-touch, robust automated deployment and setup mechanisms for the Master and Touch applications on Windows Kiosk devices, as well as Cloudflare resource provisioning.

## What was Changed

1. **Robust Windows Bootstrapping Script:**
   - Created `apps/master/installer_scripts/windows-kiosk-setup.ps1`.
   - This PowerShell script acts as the post-installation bootstrap, configuring mDNS firewall rules (UDP 5353) and App ports (TCP 8090, 8091).
   - Automatically switches the Windows Power Plan to 'High Performance' to prevent sleep during shoots.
   - Automatically injects both apps into `HKCU:\Software\Microsoft\Windows\CurrentVersion\Run` for auto-start.

2. **NSIS Installer Integration:**
   - Modified `apps/master/build/installer.nsh` to hook into `customInstall`.
   - The installer seamlessly and silently calls our PowerShell setup script with administrative bypass flags using `nsExec::ExecToLog`.

3. **Automated Cloudflare Provisioning:**
   - Improved `apps/master/scripts/cloudflare-provision.ts` to be fully interactive.
   - Instead of needing CLI flags, it asks for the Site/Hotel Name and automatically slugs it.
   - Outputs the generated D1, R2, and URL identifiers into a `.env.${destSlug}` file in the workspace root, making backend deployments a simple plug-and-play operation for new hotels.

4. **Architecture Documentation:**
   - Written `docs/ADR/002-installer-architecture.md` detailing the overarching unified installer strategy using Inno Setup as a wrapper to deploy both apps silently.

## Verification
- Verified Cloudflare provisioning logic via `--dryRun` mode: Variables evaluate correctly, missing environment checks behave expectedly, and environment files are generated perfectly formatted in the root directory.
