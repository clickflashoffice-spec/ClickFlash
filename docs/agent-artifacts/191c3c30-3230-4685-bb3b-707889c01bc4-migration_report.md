## Architecture Pattern Used

All 3 controllers follow the same Drogon pattern:

```cpp
namespace cf::http {

class XxxController : public drogon::HttpController<XxxController> {
public:
    METHOD_LIST_BEGIN
    ADD_METHOD_TO(XxxController::action, "/api/path", drogon::Get);
    METHOD_LIST_END

    drogon::Task<> action(
        drogon::HttpRequestPtr req,
        std::function<void(const drogon::HttpResponsePtr&)> callback);
};

} // namespace cf::http
```

**Key design decisions:**
- **`drogon::Task<>`** coroutines for all handlers (ready for async DB when SQLiteCpp is replaced)
- **`nlohmann::json`** for JSON serialization (not Drogon's built-in `Json::Value`)
- **`spdlog`** for logging (matching `main.cpp`)
- **`cf::http`** namespace (matching agent rules)
- **`cf::db::DatabaseManager`** with `SQLiteCpp` (matching `src/db/`)
- **`std::filesystem`** for file I/O (replacing Qt `QFile`/`QDir`)
- Private `jsonResp()` / `errorResp()` helpers to avoid repeated boilerplate
